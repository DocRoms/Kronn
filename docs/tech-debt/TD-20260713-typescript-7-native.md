- **ID**: TD-20260713-typescript-7-native
- **Area**: Frontend / Tooling / CI
- **Problem (fact)**: TypeScript 7's stable native compiler is available, but it does not expose the programmatic API required by typescript-eslint. A single-package replacement would therefore break the lint toolchain. [src: url: https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/]
- **Resolution evidence**: Kronn uses stable TypeScript 7 for `build` and `typecheck:native`, while `@typescript/typescript6` remains aliased as `typescript` for API consumers and exposes the explicit `typecheck:legacy` parity gate. A manifest regression test pins that split. [src: file: frontend/package.json:9-16] [src: file: frontend/package.json:42-64] [src: file: frontend/src/__tests__/toolchain-contract.test.ts:1-27]
- **Decision**: Adopt stable TypeScript 7 as the authoritative compiler and keep TypeScript 6 only as an API-compatibility sidecar until typescript-eslint no longer requires that API.
- **Impact**: Production builds use the native compiler without dropping ESLint coverage or hiding compatibility drift. Historical preview measurements remain archived in `docs/operations/maintenance-0.9.3-baseline.md`; they are not presented as stable-release benchmarks.
- **Where (pointers)**: `frontend/package.json` (`build` script and dev dependencies), `frontend/pnpm-lock.yaml`, `frontend/eslint.config.js`, `frontend/vite.config.ts`.
- **Suggested direction (non-binding)**: Remove the TypeScript 6 alias only after the lint stack supports TypeScript 7 without the legacy programmatic API. Do not couple that future decision to Oxlint adoption.
- **Acceptance criteria**: Met: stable TS7 build/typecheck, TS6 API parity gate, ESLint/Oxlint/test/build gates, frozen lockfile and an automated alias contract.
- **Next step**: Reopen only when the API-dependent toolchain can remove TypeScript 6.
- **Status**: RESOLVED — stable TypeScript 7 adopted with an explicit TypeScript 6 API-compatibility sidecar.
