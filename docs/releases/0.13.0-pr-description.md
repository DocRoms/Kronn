## Summary

0.13.0 unifies how Kronn reaches an agent. Codex and Claude Code now run
through the same create/resume/stream/cancel/close ACP contract as the native
ACP runtimes, with the direct CLI kept as an explicit, observable fallback;
OpenCode becomes a first-class agent on that same contract; and a separate
`http_transport` layer owns LiteLLM, NVIDIA and named OpenAI-compatible
connections, so a model incompatible with its target is refused before dispatch
rather than sent to the wrong endpoint.

Around that transport work, the release adds a durable way for an agent to put
a decision to a human and stop, image and video generation on HTTP
connections, notes as first-class objects, and a set of cost reductions that
make a turn carry what the agent has not seen instead of the whole thread.

## Changes

**Agents and transport**
- Codex and Claude Code run on the shared ACP contract by default; the direct
  CLI is reached by an explicit opt-out, and task workers take the same route
  with their narrow policy carried over — own worktree, no inherited user
  configuration, a short tool allowlist, a fresh session, no resume of a room's
  conversation.
- A scoped, audited permission broker denies filesystem and terminal requests,
  unbound sessions, out-of-project paths and unauthorized MCP servers by
  default. Project MCP servers are never inlined with credentials.
- `http_transport` separates the OpenAI-compatible codec from the ACP boundary.
  Multiple named connections can coexist, each with its own credential, tiers
  and model catalogue; discussions keep a sticky connection so an ordinary
  reply resolves through the same target.
- One catalogue contract feeds ACP agents, adapters and HTTP connections —
  live discovery when a runtime exposes it, operator configuration otherwise.
  Claude and Codex tiers can pair a model with a reasoning effort the model
  advertises.
- Installed CLI versions are compared against their upstream stable releases;
  checking never installs an update.
- OpenCode is detectable, installable and addressable everywhere, gets Kronn's
  own MCP bridge over ACP, is no longer locked out by an unreadable auth file,
  and receives a runnable Linux copy on a macOS host like the agents beside it.

**Human decisions and important messages**
- An agent can put a Decision or a Blocker to the human and stop; the card is a
  persisted object with its own place, not a formatting convention, so it does
  not scroll away.
- Publishing a card requires an enrolled credential and a single-use proof
  bound to the room and to the exact text, so a captured request cannot be
  replayed or aimed elsewhere. A worker reaching the room through the agent
  bridge publishes none while it is working; it reports through its delivery.

**Media generation**
- Image and video generation on HTTP connections, configured as modality slots
  rather than quality tiers. A generation can open its own discussion, start
  from or end on an image the discussion already holds, and a clip's last frame
  can be kept as an asset with a link back to the clip.
- A generation asking for something the provider does not take is refused at
  submission, naming what is missing, instead of queueing a job that retries
  the same refusal.

**Orchestration and delegation**
- An approved delegation publishes its report; a reassigned worker can deliver
  again after a timeout interrupted an unreviewed delivery; an execution parked
  on a worker's control offer can be redirected; a quota escalation that was
  never closed can be re-armed.
- A delegated worker hears its own room again once its task is done, recovering
  that single hop only, on proof written by the orchestrator.
- A multi-agent debate cannot reach a provider without the model check every
  other launch path applies.
- An identity Kronn does not recognize is refused instead of quietly becoming a
  Custom agent.
- An ACP agent that fails to start no longer leaves its process running.

**Cost and context**
- Eligible turns resume with a bounded delta instead of resending the whole
  thread; the prompt carries an MCP server listing instead of every server's
  documentation; automatic conversation summaries are gone, with `OnDemand` and
  `Off` as the two honest strategies.
- Discussions report their storage weight split by what a cleanup could
  actually reclaim; listing a workflow's runs no longer carries every step's
  full output.

**Notes, search and projects**
- Notes have their own place, their own search scope, an edit that says so with
  its date, and a deletion that leaves the list while keeping its tombstone in
  the transcript.
- Projects > Code fetches one folder at a time, previews HTML in place, no
  longer serves files from outside the project through a symlink, and no longer
  silently truncates the tree.

**Interface**
- The discussion header reads as two lines, its panels moved out of the header
  row, the panel strip floats over the conversation, the model catalogue is one
  sortable table, agent cards sit in two independent columns, and the Kronn
  mark is drawn rather than resampled at every size.

## Test plan

All figures below come from the principal's qualification receipts on the
candidate tree; they were not re-run for this description.

- [ ] Full Rust suite, including integrations, API and doc-tests — passing
      locally on the qualified tree, with the historical ignores unchanged.

`test-backend-coverage` are currently failing on the pushed tree and must be
green on the pushed candidate before this PR is merged.
