## What the test proves

The fixture is a disposable SQLite file, with foreign keys and WAL enabled.
It contains a project, a discussion, a Unicode/NUL message, a task and its audit
event, an orchestration run/execution, a named external connection and a linked
Quick Prompt. Snapshot comparison preserves every old column of these nine
tables and the pre-upgrade migration receipts; newly added columns are allowed.
No production data, real credential, provider or host configuration is used.
[src: file: backend/src/db/release_gate_tests.rs:746-810]
[src: file: backend/src/db/release_gate_tests.rs:883-937]

Opening through `Database::open_path` performs the actual backup/migration
path while the old connection remains open. Assertions require the new schema,
SQLite integrity and foreign-key checks, unchanged old values, and no important
card synthesized from historical message text. The co-located `config.toml`
and its backup retain their exact bytes. Opening the database backup confirms
that it still contains the old schema and all original data. A second opening
of the upgraded database preserves values, creates no duplicate migration
receipts and leaves the rollback backup byte-identical.

## Recorded run and limits

The isolated command was:

```text
cargo test --manifest-path backend/Cargo.toml --offline --locked --lib \
  persistent_0_12_upgrade_preserves_data_configuration_and_rollback_snapshot \
  -- --nocapture
```

Receipt `2560a460b516-upgrade-upgrade-013-green2.json`, retained under
`/private/tmp/release-013-takeover-proof.XMDShb`, records one passing test,
zero failures/ignores, 0.16 seconds test time and 93.673 seconds including the
build/wrapper. The before/after candidate snapshots are identical. The first
run did not compile because the new snapshot assertion needed an explicit
SQLite value type; it is retained separately and is not a product RED control.
Formatting and diff-whitespace checks also pass on the test-file blob above.

This proves normal successful migration and backup/reopen behavior on the
populated fixture. It does not prove every possible production dataset,
permissions/disk-full failures, a complete application rollback, encrypted
credential decryption, live provider execution, package installation or remote
CI. Backups are best-effort in the existing implementation; the test does not
turn a logged backup failure into a fail-closed guarantee.
